# Releasing

The version lives in `version` in `cli/Cargo.toml`. The npm packages and the Homebrew formula take it from the release. The skill stub `skills/agent-terminal/SKILL.md` repeats it in `metadata.version`, because `npx skills add` and the Claude Code plugin marketplace copy that file as it is in the repository; `cargo test` fails while the two differ.

## Cut a release

An agent cuts a release end to end with these steps. Keep npm and Homebrew state from the checks inside the checkout (`npm_config_userconfig`, `npm_config_cache`, a scratch `--prefix`).

1. **Collect the commits since the last tag.** `git fetch --tags origin`, then `git log --no-merges --format='%h %s%n%b' "$(git describe --tags --abbrev=0 origin/main)..origin/main"`. Before the first release there is no tag: take every commit on `origin/main`.
2. **Write the changelog section.** In `CHANGELOG.md`, turn the commits and any entries under `## Unreleased` into a new `## <version> (<YYYY-MM-DD>)` section, placed below an empty `## Unreleased`. Group the entries under `### Features` (`feat`), `### Fixes` (`fix`), `### Performance` (`perf`) and `### Other changes` (any other commit a user would notice, such as a new platform or install channel). Leave out `chore`, `ci`, `test` and `style` commits and anything a user can't see, and drop empty groups. Write one line per change, in the user's words, with commands and flags in backticks; a breaking change (`!` or `BREAKING CHANGE:`) comes first in its group and starts with `**Breaking:**`.
3. **Bump the version.** Set `version` in `cli/Cargo.toml` and `metadata.version` in `skills/agent-terminal/SKILL.md` to the new version, and run `cargo build` in `cli/` so `Cargo.lock` follows. Then run the release's preflight from the repository root, `node npm/preflight.js --tag v<version>`, and go on only when it ends with `v<version> can be released`.
4. **Commit.** `git commit -m "chore: release v<version>" -- CHANGELOG.md cli/Cargo.toml cli/Cargo.lock skills/agent-terminal/SKILL.md` on a branch, push it and open a pull request to `main`.
5. **Wait for CI.** `gh pr checks <pr> --watch` until every check passes, `dist plan` included, then merge the pull request.
6. **Tag and push.** `git fetch origin main`, check that `git log -1 origin/main` is the release commit, then `git tag v<version> origin/main` and `git push origin v<version>`.
7. **Watch the run.** `gh run list --workflow release.yml --branch v<version>` names the run and `gh run watch <run> --exit-status` follows it.
   - A failure before `host` (preflight, builds, npm packages, install test) has released nothing. Fix the cause on `main` through steps 4 and 5, delete the tag (`git push origin :refs/tags/v<version>`, then `git tag -d v<version>`) and tag the fixed commit.
   - A publish job that fails after `host` created the GitHub release: fix its cause and rerun the failed jobs (`gh run rerun <run> --failed`). Publishing skips versions already on npm, and the tag stays where it is.
8. **Verify each channel.**
   - GitHub: `gh release view v<version>` shows the changelog section as the notes, the six archives, a `.sha256` per archive and `sha256.sum`. Download one archive (`gh release download v<version> -p 'agent-terminal-aarch64-apple-darwin.tar.xz'`) and check `gh attestation verify agent-terminal-aarch64-apple-darwin.tar.xz --repo repost-sh/agent-terminal`.
   - npm: `npm view @repost/agent-terminal dist-tags.latest` prints the version, and `npm view @repost/agent-terminal-<platform>@<version> version` does for each platform package. `npm i -g --prefix <scratch> @repost/agent-terminal@<version>`, then `<scratch>/bin/agent-terminal --version`. In a scratch project, `npm i @repost/agent-terminal@<version>` then `npm audit signatures` reports verified attestations.
   - Homebrew: `brew update`, `brew install repost-sh/tap/agent-terminal` (`brew upgrade` when installed), then `agent-terminal --version`.

A tag with a prerelease suffix (`v0.2.0-rc.1`, from `version = "0.2.0-rc.1"`) runs the whole pipeline, preflight included, and creates a GitHub prerelease, but publishes nothing to npm or Homebrew. Use one to rehearse. Its notes are its own `## 0.2.0-rc.1 (<date>)` section or, as cargo-dist does for prereleases, the entries under `## Unreleased`; the preflight accepts either, and dry-runs the npm packages under the `next` dist-tag because npm refuses to make a prerelease `latest`.

## What the tag runs

`.github/workflows/release.yml`, generated by [dist](https://axodotdev.github.io/cargo-dist/) from `dist-workspace.toml`:

The preflight (`preflight.yml`, job `custom-preflight`, `local-artifacts-jobs` in `dist-workspace.toml`) runs `node npm/preflight.js --tag <tag>` next to the builds, on prerelease tags too. It fails when the tag isn't `v` + the version in `cli/Cargo.toml`, when `CHANGELOG.md` has no section for that version, or when `npm publish --dry-run` refuses any of the seven packages (built from the template without their binaries, which don't exist yet). Everything after the builds waits for it, so the GitHub Release and both publish jobs never start after a failed preflight.

1. Builds `agent-terminal` archives for macOS (arm64, x64) and Linux (arm64, x64, glibc and musl). The musl archives build in the `ghcr.io/rust-cross/rust-musl-cross` image for their architecture (`github-custom-runners` in `dist-workspace.toml`), because the binary compiles OpenH264, a C++ library, from source and Ubuntu's `musl-tools` has no musl C++ compiler; that image has a musl GCC with C++ and the Rust musl target.
2. `npm-packages.yml` packs one npm package per platform (`@repost/agent-terminal-<os>-<cpu>[-musl]`, holding only that binary) and the main `@repost/agent-terminal` package (the launcher in `npm/agent-terminal`, with the platform packages as exact-version optional dependencies). Every package is public (`publishConfig.access`) and names this repository (`repository`), which npm provenance needs; the scope is explained in `docs/adr/0003-npm-package-is-repost-scoped.md`. It then builds the Homebrew formula from the same archives and runs the clean-machine install test (below). Any failure stops the release.
3. Creates the GitHub Release with the archives, a `.sha256` file per archive and `sha256.sum`. Its title and notes are the version's `CHANGELOG.md` section. Each build job attests its archives with GitHub artifact attestations (`github-attestations` in `dist-workspace.toml`), so `gh attestation verify <archive> --repo repost-sh/agent-terminal` traces a download to the run that built it.
4. Publishes the formula to `repost-sh/homebrew-tap` (`brew install repost-sh/tap/agent-terminal`) and the npm packages (`publish-npm.yml`, through npm trusted publishing with `--provenance` and no token, platform packages first, versions already on npm skipped so a rerun is safe).

## Roll back

npm never lets a version number be used twice, even after unpublishing, so a bad release is contained and replaced, not undone. The npm commands need a maintainer of the `@repost` packages logged in (`npm login`); trusted publishing covers only the workflow's `npm publish`.

1. **Move npm `latest` back** to the last good version: `npm dist-tag add @repost/agent-terminal@<good> latest`. The platform packages follow, because the main package pins them exactly.
2. **Deprecate the bad version**, for the main package and each platform package: `npm deprecate @repost/agent-terminal@<bad> "<what is wrong>; use <good> or later"`, then the same for each `@repost/agent-terminal-<platform>@<bad>`.
3. **Ship a fixed patch version** through the procedure above.
4. **Update the tap formula.** The fixed release pushes its own formula to `repost-sh/homebrew-tap`. Reverting `Formula/agent-terminal.rb` there stops new installs of the bad version but doesn't move existing installs, since `brew upgrade` acts only on a higher version: only the fixed, higher version reaches them.
5. **Never move a tag** of a release that reached `host`: Homebrew and source builds rely on it. To stop the GitHub release showing as the latest, mark it a prerelease (`gh release edit v<bad> --prerelease`).

## Clean-machine install test

The `clean-install` job in `npm-packages.yml` installs the release's own artifacts on fresh runners: Ubuntu x64 and arm64 (glibc), Alpine x64 and arm64 (musl, a `node:24-alpine` container), macOS arm64 (`macos-14`) and macOS x64 (`macos-15-intel`). Each row installs with each channel: npm, pnpm and bun from a local registry holding the packed tarballs (`npm/install-test/registry.js`), the direct release archive after checking it against its `.sha256`, and the formula dist generated with its archive URLs pointed at the local archive. Alpine has no Homebrew row, because Homebrew does not run on musl. After installing (`npm/install-test/install.sh`), `npm/install-test/check.sh` asserts, with no TTY, that `--version` and `--json version` print the release's version, that the skill stub `install --skills` writes carries it, and that `open`, `snapshot` and `close` on the line-printer fixture work and `daemon stop` leaves no daemon running; `npm/install-test/offline.sh` then runs the same checks with networking cut (`sandbox-exec` on macOS, a network namespace on Linux).

It runs before any tag: `.github/workflows/clean-install.yml` builds the six archives the way `release.yml` does, from the same `dist plan`, and runs the same test on them. It runs on every pull request, and on demand from the Actions tab or with:

```sh
gh workflow run clean-install.yml --ref <branch>
gh run watch "$(gh run list --workflow clean-install.yml --branch <branch> --limit 1 --json databaseId --jq '.[0].databaseId')"
```

GitHub offers `workflow_dispatch` only for workflows on the default branch, so until `clean-install.yml` is on `main`, open a pull request (a draft is enough) to run it.

## Change the pipeline

Edit `dist-workspace.toml`, then run `dist generate` with dist 0.33.0 to rewrite `release.yml`. `release.yml` runs `dist plan` on every pull request, and that fails while the generated file is out of date, so a hand edit to `release.yml` cannot land.

A new platform needs a target in `dist-workspace.toml`, a row in `PLATFORMS` in `npm/agent-terminal/lib/platform.js`, and a row in the `clean-install` matrix in `npm-packages.yml` whose `target` and `package` name that platform; `npm/test/platform.test.js` fails until the three agree.

The two musl images are pinned by digest, so their Rust version stays fixed until the digests change. To move them to a newer Rust, take each tag's current digest (`docker buildx imagetools inspect ghcr.io/rust-cross/rust-musl-cross:aarch64-musl`, then `:x86_64-musl`) and put it in `dist-workspace.toml`.

Every release archive (dist's `include`) and every npm platform package (`build-packages.js`) ships `licenses/` next to the binary. A new third-party work built into the binary (a font, a C library) needs its licence text in `licenses/` and a row in `licenses/README.md`.

## Check locally

```sh
node --test 'npm/test/*.test.js'
dist plan
node npm/preflight.js --tag v<version>
```

To build a musl archive the way the release does, run dist in that target's image from `dist-workspace.toml` (arm64 shown; the archive lands in `target/distrib`, the Linux build in `target/musl`):

```sh
docker run --rm -v "$PWD:/src" -w /src -e CARGO_TARGET_DIR=/src/target/musl \
  ghcr.io/rust-cross/rust-musl-cross:aarch64-musl@sha256:<digest in dist-workspace.toml> \
  sh -c "curl --proto '=https' --tlsv1.2 -LsSf https://github.com/axodotdev/cargo-dist/releases/download/v0.33.0/cargo-dist-installer.sh | sh \
    && dist build --artifacts=local --target=aarch64-unknown-linux-musl"
```

To run the install test for one channel on this machine, build the release archives (`dist build`) and the formula (`dist build --artifacts=global`), turn the archives into npm tarballs (`node npm/build-packages.js --manifest <plan.json> --artifacts target/distrib --out target/npm`, then `npm pack` each directory in `target/npm/@repost`), build `line-printer`, and put the tarballs in `<artifacts>/npm`, this machine's archive and its `.sha256` in `<artifacts>/archive` and `agent-terminal.rb` in `<artifacts>/formula`. The homebrew channel installs into your Homebrew, so run it on a runner or a machine you can spare. Then, with a short `<state>` folder (the daemon's socket path lives in it):

```sh
sh npm/install-test/install.sh npm <artifacts> <state> @repost/agent-terminal-darwin-arm64
sh npm/install-test/check.sh <state> <version> <line-printer>
sh npm/install-test/offline.sh sh npm/install-test/check.sh <state> <version> <line-printer>
```

## One-time setup

- A trusted publisher on npmjs.com for each of the seven packages, `@repost/agent-terminal` and the six `@repost/agent-terminal-<platform>` (package settings, Trusted publishing): publisher GitHub Actions, organization or user `repost-sh`, repository `agent-terminal`, workflow filename `release.yml`, no environment. npm checks the workflow the tag triggered, `release.yml`, whose `custom-publish-npm` job calls `publish-npm.yml` (job `publish`, which runs `npm publish`); naming `publish-npm.yml` fails. A new trusted publisher expires unless it completes a publish within 2 days, so add them shortly before the first release. No npm token is stored in the repository. If npm refuses a trusted publisher for a package that has never been published, the first publish uses a short-lived granular token that is deleted afterwards.
- The `repost-sh/homebrew-tap` repository, and a `HOMEBREW_TAP_TOKEN` repository secret: a token with write access to its contents.
