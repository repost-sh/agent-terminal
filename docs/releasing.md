# Releasing

The version lives in one place: `version` in `cli/Cargo.toml`. The npm packages and the Homebrew formula take it from the release.

## Cut a release

1. Bump `version` in `cli/Cargo.toml`, run `cargo build` in `cli/` so `Cargo.lock` follows, and merge to `main`.
2. Tag that commit `v<version>` and push the tag.

A tag with a prerelease suffix (`v0.2.0-rc.1`) runs the whole pipeline and creates a GitHub prerelease, but publishes nothing to npm or Homebrew. Use one to rehearse.

## What the tag runs

`.github/workflows/release.yml`, generated by [dist](https://axodotdev.github.io/cargo-dist/) from `dist-workspace.toml`:

1. Builds `agent-terminal` archives for macOS (arm64, x64) and Linux (arm64, x64, glibc and musl).
2. `npm-packages.yml` packs one npm package per platform (`agent-terminal-<os>-<cpu>[-musl]`, holding only that binary) and the main `agent-terminal` package (the launcher in `npm/agent-terminal`, with the platform packages as optional dependencies). It then runs the clean-machine install test: `npm i -g agent-terminal` from a local registry in fresh Debian and Alpine containers (x64, arm64) and on macOS runners (arm64, x64), then `open` and `snapshot` on the line-printer fixture (`npm/install-test/run.sh`). Any failure stops the release.
3. Creates the GitHub Release with the archives.
4. Publishes the formula to `repost-sh/homebrew-tap` (`brew install repost-sh/tap/agent-terminal`) and the npm packages (`publish-npm.yml`, platform packages first, versions already on npm skipped so a rerun is safe).

## Change the pipeline

Edit `dist-workspace.toml`, then run `dist generate` with dist 0.33.0 to rewrite `release.yml`. `release.yml` runs `dist plan` on every pull request, and that fails while the generated file is out of date, so a hand edit to `release.yml` cannot land.

A new platform needs a target in `dist-workspace.toml`, a row in `PLATFORMS` in `npm/agent-terminal/lib/platform.js`, and a row in the install-test matrix in `npm-packages.yml`.

## Check locally

```sh
node --test 'npm/test/*.test.js'
dist plan
```

To run the install test for one Linux target in Docker, build the release archives (`dist build`), turn them into npm tarballs (`node npm/build-packages.js --manifest <plan.json> --artifacts target/distrib --out target/npm`, then `npm pack` each directory), build `line-printer` for the musl target, and run:

```sh
docker run --rm -v "$PWD/<tarballs>:/tarballs:ro" -v "<line-printer>:/fixture/line-printer:ro" \
  -v "$PWD/npm/install-test:/install-test:ro" node:24-alpine \
  sh /install-test/run.sh /tarballs /fixture/line-printer agent-terminal-linux-arm64-musl
```

## One-time setup

- `NPM_TOKEN` repository secret: an npm automation token allowed to publish `agent-terminal` and the six `agent-terminal-<platform>` packages.
- The `repost-sh/homebrew-tap` repository, and a `HOMEBREW_TAP_TOKEN` repository secret: a token with write access to its contents.
